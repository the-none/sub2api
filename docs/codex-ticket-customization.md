# Codex Ticket 采集配置

此功能位于定制分支，保留了官方 0.2.6 曾提供的 ticket 采集与注入能力。官方新版已从主线历史移除该功能，后续同步上游时需要单独维护。

## 管理入口

- 系统设置 → 网关 → Codex 设置 → Codex Ticket 采集：全局总开关、默认参与、采集代理、模型、提示词、时间参数、缺票策略和并发上限。此区域独立保存。
- 新建账号：选择 Ticket 参与状态。
- 编辑账号 → Codex Ticket 采集：选择继承、开启或关闭；可整组覆盖模型、提示词与时间参数，并选择已有的采集代理。Ticket 区域独立保存，不需要再提交账号表单。
- 批量编辑：仅修改参与状态，不覆盖各账号已有的模型、提示词、时间或代理配置。

只有 OpenAI OAuth/setup-token 且不是 Shadow 的账号参与。全局总开关优先于账号开关。账号关闭时同时停止采集、注入及缺票拦截；账号未启用时不采集。

## 参数与调度

默认维持旧行为：符合条件的账号继承全局开启状态，模型为 `gpt-6-astra` 与 `gpt-5.6-sol`，系统指令为 `Reply with exactly: pong`，用户消息为 `ping`。

| 参数 | 默认值 | 含义 |
|---|---:|---|
| 基础重试间隔 | 6 秒 | 失败后的最短重试间隔，连续失败会退避并随机错峰 |
| 单次请求超时 | 25 秒 | 上游采集 HTTP 请求的超时时间 |
| 本地有效期 | 3600 秒 | 从采集成功时间推算；不能代表上游保证的真实有效期 |
| 提前续期 | 600 秒 | 只在临近到期时重新采集；后台可设置为 0 |
| 最大退避 | 300 秒 | 连续失败的最大重试间隔 |
| 最大并发 | 4 | 每个服务实例的自动与手动采集合计上限 |
| 目标长度 | 292 | 高级设置；还会校验 HTTP 状态与票据前缀 |

每个账号、模型独立维护下一次尝试时间。401、403、429 会进入较长冷却，最长仍受最大退避限制。手动采集可以提前续期，但不能绕过正在执行的任务、并发上限或失败冷却。续期失败保留尚未过期的旧票。

模型填写实际出站名称。账号选用的模型列表会覆盖全局列表。缺票策略只作用于开启 Ticket 的账号及其所选模型，调度与 HTTP/WS 注入使用同一策略。

配置约 5 秒内热更新。本实例的全局设置、批量开关、账号关闭/删除及专用策略写入与任务启动、票据发布共用可取消的读写许可与版本边界：写入前取消旧任务，旧快照不能在写入成功后再启动或发布。已经进入持久化的任务先完成，再允许策略写入返回，避免把数据库提交与取消信号的竞态误当成“已阻止落库”。此机制不提供跨实例协调。

配置读取通过 singleflight 合并并发请求，I/O 不持有缓存锁；失败后短暂复用最后有效值。已确认保存的配置直接更新本实例缓存，存储故障不会恢复为启动时的旧开关。

未编辑的账号表单随轮询同步继承值；有未保存修改时，如服务器配置变化，会提示重新加载。保存携带配置版本并在服务端核验，旧版本返回冲突。通用账号更新在数据库行锁内保留最新 Ticket 策略，不能用旧的完整 extra 覆盖专用保存。全局参数调整不会延长已经采集的票据期限，新有效期适用于后续采集。

## 状态与日志

账号界面每 5 秒刷新采集状态，显示上次尝试、成功时间、下次计划、连续失败次数、HTTP 状态以及缺少代理、鉴权失败、超时、响应头缺失、票据长度不符等原因。不会返回票据原文或代理密码。

运维监控 → 系统日志中搜索 `openai_codex_ticket` 可继续查看服务端采集记录，并按账号 ID、模型筛选。

尝试计数、退避和在途任务属于单个服务实例，重启会重置；已成功持久化的票据仍可恢复。多实例部署尚无跨实例采集锁，多个实例可能分别采集同一账号。这些限制同样适用于手动操作和状态查看。

清除后台采集代理表示恢复配置文件的代理；要彻底停止采集，应使用全局或账号开关。账号指定代理从已有代理管理中选择，不改变业务请求的代理。

## 存储与兼容

全局新参数存入现有 settings 表的 `openai_codex_ticket_config`，总开关与默认采集代理兼容既有设置键。账号参与开关保存于 `extra.codex_ticket_enabled`（`null` 表示继承），其他覆盖保存于 `extra.codex_ticket_policy`。两者均进入调度快照，原始票据不进入调度索引投影。

无需数据库结构迁移。旧账号没有覆盖字段时继承现有行为；原有票据的防覆盖、导出脱敏、账号及模型隔离保持有效。

## 备份代理引用

备份使用 `ticket_proxy_key` 表示采集代理，并包含仅供 Ticket 使用的代理。导入时重新映射到目标数据库 ID。对于不带稳定引用的旧备份或未导出代理的备份，清除本地数值 ID 并关闭该账号的 Ticket 采集，在导入结果中提示重新选择代理；不会误用目标库的同号代理或默默改用全局代理。

文件、环境变量与管理 API 使用相同的参数校验。提前续期为 0、空系统指令均会保留；无效 TTL/续期组合、并发范围、模型列表及代理 URL 在启动或保存时拒绝。

锁许可等待跟随调用方 context 取消；采集服务关闭不会被正在执行的配置写入挡住。手动请求在校验期间取消时会终止，不能转为服务级后台任务；已取消的配置读取优先使用最后有效缓存，不会把已关闭开关恢复成启动值。
